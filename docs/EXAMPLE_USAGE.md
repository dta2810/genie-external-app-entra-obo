# Example usage

Open the app URL, sign in as an assigned user, and ask a question. The demo data has 8 claims: 4 in `east`, 4 in `west`.

## 1. Ask the claims space

Starter questions in the Genie space:

- "How many claims are there by region?"
- "What is the total claim amount by customer?"

The space answers only from the `claims` table. Answers with SQL show it in a "SQL generated by Genie" panel, followed by the rows.

## 2. Personas: same question, different rows

Put yourself in one persona group, then ask the same question:

```bash
setup/groups.sh <account-profile> <workspace-id> <you@company.com> east
```

- In `genie_obo_east`: the 4 east rows only.
- In `genie_obo_west`: the 4 west rows.
- In no group: 0 rows.
- In both groups: all 8 rows and unmasked `national_id`. `groups.sh` keeps you in one group only.

`national_id` is masked to `***-**-` plus the last 4 digits unless you are in both groups.

The row filter and mask run in Unity Catalog. The app and the prompt play no part.

## 3. Identity and token panel

The side panel shows:

- **Who am I**: the Databricks user and the token claims (`iss`, `aud`, `idtyp`, `upn`, `scp`, `exp`, minutes to expiry). Display only.
- **Auth events**: one line per step of each Databricks call (token refresh, backoff, retry).

## 4. Simulate token expiry (demo)

The **Simulate token expiry** button needs `ENABLE_DEBUG=true`. Without it, the button is hidden and `/api/debug/expire` returns 404.

1. Set `ENABLE_DEBUG=true` in `infra/config.local.env`, then re-run `infra/deploy.sh`.
2. Click **Simulate token expiry**. The next Databricks call sends an invalid token.
3. Ask a question. Watch **Auth events**:
   - `simulated expired token sent`
   - `HTTP <status> token rejected, forcing refresh via MSAL refresh token`
   - `new access token acquired, retrying once`
4. Set `ENABLE_DEBUG=false` and re-run the deploy when you are done.

How the refresh works: [AUTH_AND_TOKENS.md](AUTH_AND_TOKENS.md#how-token-expiry-is-handled).

## 5. Feedback (thumbs up / down)

Each completed answer shows 👍 / 👎.

- The app sends the rating to Genie as the signed-in user. It calls the feedback endpoint of the message with `POSITIVE`, `NEGATIVE`, or `NONE`.
- On 👎 you can add a comment. The comment is a Public Preview field of the Genie API.
- Click the active rating again to clear it. The app sends `NONE`.
- The rating shows in the Genie space's **Monitoring** tab, attributed to you.
- The audit log records the rating and whether a comment was given. It never records the comment text.

Databricks has no built-in feedback notification. To alert on new feedback, poll the API on a schedule into a Delta table and use a SQL alert.
